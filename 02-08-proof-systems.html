证明系统：三个群元素为什么够

前面几个模块把「计算」变成了「多项式恒等式」，又把它压缩成「承诺 + 打开」。 这一页把零件装起来，看 Groth16、PLONK、STARK 三家分别怎么组装 —— 以及为什么它们的证明大小差三个数量级。

综合模块 ≈ 20 min 难度 4 / 5 前置：算术化 · 承诺 · Fiat–Shamir 后续：递归 · 工程实现

01这个模块要解决的问题

到上一模块为止，你手上有一个 QAP 恒等式和一个多项式承诺方案。 问题是：怎么把它们变成一个 200 字节、能被任何人验证的字符串？

要同时满足四件事，而它们互相冲突：

  • 短：证明不能随电路规模增长。
  • 快验：验证时间最好常数。
  • 零知识：不能泄露见证。
  • 可靠：伪造成功的概率可忽略。

三家方案的差别，本质上是在这四件事上做了不同的取舍， 而不是「谁更先进」。

02三条技术路线，一张图看清

路线核心机制证明里装了什么
Groth16配对 + 电路专用设置3 个群元素，全部约束被「焊死」在设置参数里
PLONK多项式承诺 + 置换论证约 9 个群元素，电路结构以选择子多项式形式参与
STARK哈希 + FRI + AIR大量 Merkle 路径和折叠轨迹，几十到几百 KB

一个重要观察：证明大小和「电路的通用性」是反向的。 Groth16 把电路完全编译进设置，所以证明最小，但换电路要重做仪式； STARK 完全不依赖电路结构，所以证明最大，但任何电路都能即插即用。

03Groth16：把恒等式焊进配对

Groth16 的核心洞察是：QAP 恒等式本身就含「乘」和「加」， 而配对恰好能把「指数上的乘法」变成「群里的加法」。两者结构天然匹配。

证明的形状

π = ( A, B, C )  ∈  𝔾1 × 𝔾2 × 𝔾1 这就是全部。BN254 上压缩后约 128 字节

验证等式

e(A, B) = e(α, β) · e( Σi xi·Ki , γ ) · e(C, δ) 三次配对，与电路规模完全无关

A、B、C 是怎么算出来的

上面的验证等式只说了「怎么验」。真正让很多人卡住的是：这三个点由什么组成？ 下面这组公式来自 Groth16 原文，符号与你前面见过的 QAP 一一对应。

A = [ α + Σi=0m ai·ui(τ) + r·δ ]1
B = [ β + Σi=0m ai·vi(τ) + s·δ ]2
C = [ Σi=l+1m ai·( βui(τ) + αvi(τ) + wi(τ) ) / δ + h(τ)t(τ)/δ + s·A + r·B − rs·δ ]1 所有运算都在标量域里；[·]₁ 表示映射到 G1，[·]₂ 表示映射到 G2
成分作用
α, β把「设置阶段的随机性」混进证明，使 A、B 无法被拆解还原
Σ aiui(τ)把见证「求值」到 τ 点上 —— 这是 QAP 的核心动作
r·δ, s·δ盲化因子。没有它们，A、B 会泄露见证的线性组合
h(τ)t(τ)/δ商多项式的贡献，保证「约束确实被满足」
s·A + r·B − rs·δ抵消盲化因子在配对时产生的交叉项，使验证等式恢复平衡
求和下界 l+1前 l 个是公开输入（放进验证等式的 γ 项），从 l+1 开始才是私密部分
i
为什么 C 里要「减掉 rs·δ」

因为验证时要算 e(A,B)，而 A 和 B 各自带了 rδ、sδ。 展开后会出现 e(δ,δ)rs 这个多余项。 在 C 里预先减掉 rs·δ，配对时正好抵消 —— 这是「为了配对的代数平衡而做的补偿」，不是安全机制。

PLONK 的验证等式长什么样

PLONK 不用三个固定点，而是用批量打开把多个承诺合并检查。简化形式是：

e( Wζ + ζ·Wζω , [x]2 ) = e( ζ·Wζ + Wζω + F , [1]2 ) W 是两个打开证明点，F 是「线性化多项式」的承诺，ζ 是求值点

看起来只有两个配对，但 F 内部组合了门约束、置换约束、查找约束的所有项。 PLONK 把复杂度藏进了 F，而不是摊在等式表面。 这也是为什么它的证明元素更多（约 9 个），但验证依然只要两次配对。

符号含义
α, β, γ, δ设置阶段生成的四个随机标量，公开为群元素。γ 和 δ 用来把「公开输入部分」和「私密部分」分开。
Ki设置阶段算好的常量点，编码了「第 i 个公开输入如何影响约束」。
xi第 i 个公开输入的值。这是验证者唯一需要读的数据。
e(·,·)双线性配对。整个等式的含义是「两边在指数上相等」。

为什么是三个而不是两个

因为 QAP 恒等式有三组系数：Ai(x)、Bi(x)、Ci(x)。 配对只能处理「两个群的元素相乘」，所以要表达 A·B = C 这种三元关系， 必须有两个元素在 𝔾1、一个在 𝔾2（或者反过来），才能凑出三次配对。

这不是随便选的：三个群元素是信息论意义上的下界。 Groth 的论文标题就叫《On the Size of Pairing-based Non-interactive Arguments》—— 他证明了在配对模型下，想表达这类关系，至少需要这么多。

i
代价：电路专用

Ki 这些常量点是在设置阶段按具体电路算出来的。 电路改一行，整套参数作废，必须重跑仪式。 这是 Groth16 最大的工程负担，也是 PLONK 出现的主要动机。

04PLONK：把电路变成选择子多项式

PLONK 的关键改变：不再把电路「编译进设置」，而是把电路写成若干条公开的多项式， 让证明者去承诺它们。这样同一套设置可以服务任意电路。

证明里有什么

承诺对应什么数量
a, b, c三列信号的取值多项式3
z置换论证的累乘多项式1
tlo, tmid, thi商多项式 h(x) 被切成三段（因为次数超过设置上限）3
Wζ, Wζω批量打开的两个证明点2

总共约 9 个群元素。验证时用「批量打开」把它们压成两次配对检查。

核心恒等式

qLa + qRb + qMab + qOc + qC + PI(x) = t(x)·ZH(x) 左边是「门约束 + 公开输入」，右边是「商多项式 × 消失多项式」
符号含义
qL,qR,qM,qO,qC五个选择子多项式，编码「这一行是什么门」。公开，由电路决定。
a, b, c三列信号多项式，私密，由证明者填充。
PI(x)公开输入多项式，在对应行上取公开值。
ZH(x)xn−1，在 n 个单位根上全为零。
t(x)商多项式，证明者算出并承诺。

为什么比 Groth16 大

因为 PLONK 把「电路结构」也变成了需要承诺的对象的一部分（选择子虽然是公开的， 但置换 σ 和商多项式 h 都要承诺）。多出来的承诺，就是通用性的票价。

✓
但它换来了两件事

① 通用设置：一次 Powers of Tau 仪式，所有电路复用。
② 可更新：后续可以增量添加参与者，不需要推倒重来。

05STARK：不用椭圆曲线的另一条路

STARK 完全不碰配对。它把计算写成「状态转移表」，用哈希承诺这张表， 再用 FRI 证明「这张表的每一行都满足转移规则」。

三个组成部分

1

AIR：把计算写成状态机

每一行是一个时刻的完整状态，相邻两行之间必须满足转移约束： Transition(rowi, rowi+1) = 0。 适合虚拟机、循环、任何「一步步推进」的计算。

2

低度扩展：把表变成多项式

对每一列插值出多项式，然后在更大的域上求值（通常是 4–8 倍）。 这样「表满足约束」就变成「多项式在扩展域上满足某个低度条件」。

3

FRI：证明它是低次的

用折叠协议证明「这个多项式次数不超过 d」，全程只需要哈希。 证明就是一堆 Merkle 路径 + 每轮的折叠值。

验证者检查什么

  • 抽查若干个位置的 Merkle 路径，确认取值一致；
  • 检查每轮折叠后的值满足递推关系；
  • 确认最终剩下的常数多项式次数符合预期。

全是哈希运算，没有任何椭圆曲线操作 —— 这就是它抗量子的原因。

!
代价非常具体

证明大小 O(log² d) 条 Merkle 路径，典型 50–200 KB。 链上验证的 gas 是以太坊上 Groth16 的几十倍。 所以 STARK 通常配合「递归」使用：链下生成 STARK，再用一个很小的 Groth16 包装它上链。

07怎么选：三个问题定方向

1

要不要上链，且 gas 敏感？

要 → Groth16 或 PLONK。48–800 字节的证明在以太坊上是几万到二十几万 gas， STARK 的几十 KB 直接贵一个数量级。

2

电路会频繁改动吗？

会 → PLONK。Groth16 每次改电路都要重跑仪式，在快速迭代期是灾难。 电路稳定、且要极致省 gas → Groth16。

3

需要抗量子，或者完全不想碰仪式？

是 → STARK。这两条它都满足，代价是证明大。常见做法是「STARK 证明 + Groth16 包装」， 把两个优点拼起来。

08小结与常见误区

你应该带走的

  • Groth16 的证明是 (A,B,C) 三个群元素，验证三次配对，电路专用设置。
  • 三个元素是配对模型下的下界，不是实现偷懒。
  • PLONK 把电路写成选择子多项式，换来通用设置，代价是证明变大。
  • STARK 用 AIR + FRI，全程哈希，证明大但抗量子、无需设置。
  • 「STARK 生成 + Groth16 包装」是常见的混合方案。
✕「Groth16 是老技术，应该被淘汰了。」
✓
它的证明大小和验证成本至今仍是最优。在 gas 敏感的场景（L1 验证、跨链桥）， 它仍然是首选。新方案主要在「通用性」和「无需仪式」上胜出，不是在「小」上。
✕「PLONK 就是 Groth16 的升级版。」
✓
两者是不同的取舍，不是版本关系。PLONK 用更大的证明换通用设置和更强表达力。 如果电路固定且 gas 极敏感，Groth16 仍然是更好的选择。
✕「STARK 证明大，所以不适合区块链。」
✓
StarkNet 就在生产环境跑。关键看验证成本能否被分摊： 一个批次几千笔交易，几十 KB 的证明摊到每笔只有几十字节。
✕「三个系统可以随意混用组件。」
✓
算术化、承诺、证明系统三者有耦合约束。比如 AIR 配 KZG 就要额外做低度测试， 而 FRI 配 R1CS 需要把约束转成多项式形式。混搭可行，但不是拼积木。
