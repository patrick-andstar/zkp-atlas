承诺方案：先锁住，后打开

「我现在把答案的哈希给你，明天再公布答案。」这句话里藏着两个必须同时成立的性质： 你现在猜不到答案，但明天也改不了答案。 这就是承诺方案，也是所有零知识协议的原子操作。

基础原语 ≈ 13 min 难度 2 / 5 前置：哈希 · 椭圆曲线 · 00 · 02 同态 被用于：KZG · Pedersen · 一切协议

01这个模块要解决什么问题

承诺方案是一个两阶段的协议。第一阶段「锁」，第二阶段「开」。锁上之后， 承诺者既不能改内容，也不能让别人看到内容。

Commit( m ) → ( C, r )   ← 把消息 m 和随机数 r 变成一个承诺 C
Open( C, m, r ) → 接受 / 拒绝   ← 验证者检查 C 确实对应 m

为什么需要随机数 r？因为如果只是 C = H(m)， 面对一个小的消息空间（比如「是/否」），验证者可以穷举出 m。 加入随机盐之后，同一个 m 每次承诺都不同。

i
它在 ZKP 里的位置

几乎每一个交互式证明的第一句话都是「我先承诺」。Schnorr 里的 R = gr 是承诺， KZG 里的 [p(τ)]₁ 是承诺，FRI 里的 Merkle 根也是承诺。 没有承诺，就没有「先锁后揭」的时间结构，也就没有零知识。

02直觉：把答案放进信封，封口盖上蜡印

你和朋友打赌，你先写下答案，装进信封，封好，放在桌上。第二天打开。

  • 他不能偷看 —— 信封不透明（隐藏性）。
  • 你不能换 —— 蜡印完好，换信封会被发现（绑定性）。

承诺方案就是这个信封的数学版本。但有一个微妙之处：数学上「不透明」和「不能换」 不能同时做到完美。

统计隐藏 + 计算绑定   或   计算隐藏 + 统计绑定 二选一。不能同时「信息论意义上」安全

为什么？直觉上：如果 C 完全不含 m 的信息（统计隐藏）， 那它必然对应多个可能的 m —— 绑定性就只能在计算上成立（假设对手算不出是哪个）。 反之亦然。

03两个性质，说清楚「对谁安全」

性质定义防的是谁
隐藏性
hiding		 给定 C，无法区分它对应 m₀ 还是 m₁ 接收方（验证者想偷看）
绑定性
binding		 无法找到 (m, r) ≠ (m', r') 都能打开同一个 C 承诺方（证明者想反悔）

两种安全强度

  • 统计安全：即使对手有无穷算力也攻不破。
  • 计算安全：只对多项式时间对手成立，依赖某个困难问题。

ZKP 里最常用的组合是「统计隐藏 + 计算绑定」： 证明者不能反悔（绑定性靠密码学），但验证者即使有量子计算机也偷看不到（隐藏性靠信息论）。 这个组合对零知识最有利。

04最简单的方案：哈希承诺

C = H( m ‖ r ) ,    r ← {0,1}λ 打开时给出 (m, r)，验证者重算哈希比对
性质成立条件
隐藏性哈希像随机函数 + r 足够长。没有 r 时，小消息空间可被穷举
绑定性哈希抗碰撞。找到两个不同输入同哈希，就能反悔

优点：简单、快、只需要哈希。缺点：没有代数结构 —— 你不能在承诺上做运算（比如「证明两个承诺的和等于第三个」）。

!
一个必须注意的细节

H(m ‖ r) 里的拼接必须有唯一解码。 如果 m 长度可变，m="ab", r="c" 和 m="a", r="bc" 可能产生相同输入。 标准做法是固定长度或用长度前缀。

05Pedersen 承诺：带同态的那一个

如果承诺需要支持「加法」，就得用 Pedersen。它是所有同态承诺的原型。

C = m·G + r·H G、H 是两个公开的群元素，且没人知道它们之间的离散对数关系
符号含义
m被承诺的消息（一个标量）
r随机盲化因子，均匀取自 𝔽p
G, H群的两个生成元。关键：没人知道 H = k·G 里的 k

隐藏性：为什么 r 能掩盖 m

r·H 在群里均匀分布（因为 r 均匀）。加上 m·G 只是平移， 平移后的分布仍然均匀 —— 所以 C 与 m 无关。这是统计隐藏。

绑定性：为什么必须「没人知道 k」

假设攻击者知道 H = k·G。他想用 (m', r') 打开同一个 C，需要

mG + rH = m'G + r'H  ⟹  ( m − m' ) = k·( r' − r ) 知道 k 就能解出任意 (m', r')，绑定性崩溃

所以 Pedersen 的绑定性等价于「离散对数问题难解」。这也是为什么 G 和 H 必须用「nothing up my sleeve」的方式生成 —— 否则创建者可能知道 k。

同态性：为什么它这么有用

C1 + C2 = ( m1 + m2 )·G + ( r1 + r2 )·H 两个承诺相加，等于「消息相加」的承诺。全程不知道 m₁、m₂

这个性质让「余额保密但可验证总和」成为可能：每笔转账承诺一个金额， 把所有承诺加起来，验证总和为零 —— 而没人知道任何一笔的金额。

06Merkle 承诺：承诺一个向量

前两种承诺的都是「一个标量」。如果要承诺「一百万个值」，并且能单独打开其中一个， 就需要 Merkle 树。

C = MerkleRoot( v1, …, vn ) 打开第 i 项：给出 v_i 和 log n 个兄弟哈希
维度Merkle
承诺大小32 字节（一个哈希）
打开大小O(log n) 个哈希
绑定性哈希抗碰撞
隐藏性无（叶子是明文哈希，可穷举）
同态无

Merkle 承诺没有隐藏性 —— 如果叶子空间小，别人可以逐个试。 所以用它的时候通常要加盐，或者只承诺本来就公开的数据（比如 FRI 的求值表）。

多项式承诺是这里的「第四种」

KZG 可以看成 Pedersen 的升级版： 不是承诺一个标量，而是承诺一整个多项式，并且支持在任意点打开。 它把「同态」和「单点打开」两件事同时做到了。

08小结与常见误区

你应该带走的

  • 承诺 = 先锁后开，要求隐藏性和绑定性同时成立。
  • 两者不能同时统计安全，必须选一边；ZKP 常用「统计隐藏 + 计算绑定」。
  • 哈希承诺简单、抗量子，但没有代数结构。
  • Pedersen 承诺 C = mG + rH 支持同态加法，绑定性依赖 DL 假设。
  • Merkle 承诺适合向量，打开大小 O(log n)，但没有隐藏性。
✕「承诺就是加密，打开就是解密。」
✓
加密有密钥，可逆；承诺没有密钥，靠的是「打开时提供原像」。 而且承诺必须防「承诺者反悔」，加密不要求这一点。
✕「哈希承诺已经够用了，不需要 Pedersen。」
✓
一旦你需要在承诺上做运算（比如证明「输入之和 = 输出之和」）， 哈希承诺就无能为力了。同态性是 Pedersen 存在的唯一理由。
✕「Pedersen 里的 H 可以随便取一个点。」
✓
如果创建者知道 H = kG 的 k，他就能伪造打开。 H 必须用可验证的随机方式生成（比如哈希 G 的坐标再映射到曲线）。
✕「承诺的隐藏性是绝对的。」
✓
取决于方案。Pedersen 是统计隐藏（绝对），哈希承诺是计算隐藏（依赖哈希）。 Merkle 则根本没有隐藏性。
