多项式承诺：把一整个多项式锁进 48 字节

上一模块把电路变成了多项式恒等式。但多项式有几万项，直接发给验证者等于没压缩。 多项式承诺解决的就是这件事：用一个固定大小的值代表整个多项式，并且能证明它在某点的取值。

核心模块 ≈ 18 min 难度 4 / 5 前置：椭圆曲线 · 配对 后续：证明系统

01这个模块要解决什么问题

假设你是证明者，手里有一个一万次的多项式 p(x)。你要让验证者相信两件事： ① 你承诺的确实是这个 p，之后不能偷偷换；② p(z) = v 这个值是对的。

最笨的办法是把一万个系数全发过去。验证者自己算 p(z) —— 这需要传输 32 KB，计算一万次乘加。

而 SNARK 的目标是：证明 200 字节、验证 3 毫秒。所以必须有一种机制， 让「多项式」这个对象可以像哈希值一样被固定住、被引用、被验证。

它在流水线的哪个位置

算术化产出的是 QAP 恒等式： P(x) = h(x)·Z(x)。要验证这个等式，验证者需要在随机点 z 上取 P(z)、h(z)、Z(z) 的值。 但 P 的系数里含私密见证 —— 不能直接给。

于是证明者对这些多项式做承诺，然后证明「在 z 点，这些承诺对应的取值满足那个恒等式」。 多项式承诺就是这套「可验证取值」的机制。

02直觉：把多项式锁进盒子，钥匙是「某个点的取值」

想象你把多项式 p 装进一个透明但锁死的盒子。盒子外面贴着一个标签 C， 这个标签由 p 唯一决定，但看不出 p 长什么样。

现在有人问：「p(7) 是多少？」你不能打开盒子，但你可以出示一张收据， 证明「盒子里的东西在 7 处确实等于 42」。收据很小，验证者看一眼就能确认， 而且无法伪造 —— 除非他能换掉盒子里的东西。

承诺 C  +  打开证明 π  →  验证者相信 p(z) = v C 固定「是哪个多项式」，π 固定「这一点的值」

关键在于：同一份承诺只能对应一个多项式。如果证明者能对同一个 C 给出两个不同的 p(z)，整个系统立刻崩塌。

03两个必须的性质（而且不能同时做到完美）

为什么两者不能同时是「统计安全」

这是一个通用结论：任何承诺方案，都无法同时做到「统计隐藏」和「统计绑定」。 因为如果 C 完全不包含信息，那它必然对应多个可能的原像 —— 绑定性就没了。 实践中必须选一边：计算绑定 + 统计隐藏（KZG、Pedersen）是最常见的组合。

04KZG：四个步骤，两个公式

KZG 出自 Kate、Zaverucha、Goldberg 2010 年的论文。它的证明只有一个群元素（32–48 字节）， 验证只要两次配对。代价是需要可信设置。

1

Setup：生成 τ 的幂

随机取一个秘密 τ ∈ 𝔽p，计算并公开：

[τ0]₁, [τ1]₁, …, [τd]₁   和   [τ]₂ [x]₁ 表示「把标量 x 映射到 G1 群上的点」；d 是支持的最大多项式次数

然后必须把 τ 彻底销毁。这是整个方案唯一的信任假设。

2

Commit：承诺

给定 p(x) = Σi pixi，承诺是：

C = [ p(τ) ]₁ = Σi pi · [τi]₁ 本质是把「求值」搬到指数上，用椭圆曲线加法代替域乘法

注意这里发生了什么：证明者不知道 τ，但他能用公开的 [τi]₁ 线性组合出 [p(τ)]₁。这就是「在不知道秘密的情况下计算秘密的函数值」。

3

Open：证明某点的取值

要证明 p(z) = v，先构造商多项式：

q(x) = ( p(x) − v ) / ( x − z ) 因为 p(z) = v，分子在 x=z 处为零，所以一定能整除，q 是个正常的多项式

然后发送打开证明 π = [q(τ)]₁。就一个群元素。

4

Verify：两次配对

验证者手上只有 C、π、z、v，检查：

e( C − [v]₁ , [1]₂ ) = e( π , [τ]₂ − [z]₂ ) e 是双线性配对；[v]₁ 和 [z]₂ 都可以由公开参数直接算出

为什么这个等式成立

把 C = [p(τ)]₁、π = [q(τ)]₁ 代进去，两边在指数上分别是：

左边：p(τ) − v
右边：q(τ) · ( τ − z )

而由 q(x) = (p(x) − v)/(x − z) 移项即得 p(τ) − v = q(τ)·(τ − z)。两边相等，所以配对等式成立。

✓
这一步的漂亮之处

验证者从头到尾没有见过任何系数，也没有做任何与次数相关的运算。 不管多项式是一万次还是一亿次，验证都只是两次配对 —— 常数时间。

符号速查

符号含义
τ可信设置生成的秘密标量，必须销毁。所有安全性都建立在「无人知道它」之上。
[x]₁标量 x 在 G1 群上的像，即 x·G，G 是 G1 的生成元。
[x]₂同上，但在 G2 群上。配对需要两个不同群的元素。
e(·,·)双线性配对，满足 e(aP, bQ) = e(P,Q)ab。
d支持的最大多项式次数。仪式生成 d+1 个 G1 点，d 越大，仪式越久、参数越大。

05为什么 τ 泄露就等于系统崩了

假设攻击者知道了 τ。他可以为任意多项式构造承诺， 更致命的是：他能对同一个承诺 C 打开出任意值。

攻击怎么进行

想在点 z 声称 p(z) = v'（而真实值是 v）。他需要构造 π' 让验证等式成立。由于知道 τ，他可以直接算出需要的标量：

π' = [ ( p(τ) − v' ) / ( τ − z ) ]₁ 只要 τ ≠ z，这个除法总能算出来 —— 而 τ 是随机值，几乎必然 ≠ z

于是他可以让任何命题通过验证，且不留下任何痕迹。验证者无法区分真证明和假证明。

!
这不是「最好删掉」，是「必须删掉」

而且删除必须发生在生成参数的那个进程里，不能「算完写到文件再删」—— 中间任何一刻的磁盘快照、内存转储、swap 文件都可能导致泄露。 这就是为什么真实仪式要用 MPC 多方接力，把风险摊薄到「N 个人里只要 1 个诚实」。

06FRI：不用秘密的路线

FRI（Fast Reed–Solomon Interactive Oracle Proof of Proximity）走的是另一条路： 完全不碰椭圆曲线和配对，只用哈希函数。

核心思想：如果它是低次多项式，折叠后仍然是低次

把多项式 p(x) 拆成偶数项和奇数项：

p(x) = peven(x²) + x · podd(x²) 拆完后，问题规模减半：原来次数是 d，现在两个子多项式次数都是 d/2

引入随机挑战 α，构造折叠后的新多项式：

p'(x) = peven(x) + α · podd(x) 次数减半。重复 log d 次，最后变成一个常数，直接发过去就行

验证者每轮只需要检查「新多项式的取值和旧多项式在对应点的取值一致」。所有检查都是哈希运算。

可信设置需要不需要

07IPA：只要离散对数，不要配对

Inner Product Argument 用 Pedersen 承诺：C = ⟨p, G⟩，其中 G 是一组群元素。 打开时，证明者证明「我知道系数 p，且 ⟨p, G⟩ = C 且 ⟨p, b⟩ = v」。

它通过递归折半，把长度为 n 的内积论证压缩到 O(log n) 个群元素。 不需要可信设置，也不需要配对 —— 只需要离散对数难解。

i
代价在哪

验证时间是 O(n)（或经过预处理的 O(log n)，但常数很大）。 所以 IPA 适合「证明者多、验证者少、且不需要极短验证」的场景，比如 Halo2 的递归电路内部。

怎么选

  • 链上验证、gas 敏感 → KZG。一个 G1 点就能当证明（BN254 上 32 字节，BLS12-381 上 48 字节），在以太坊上只要几万 gas。
  • 要抗量子、不想搞仪式 → FRI。接受证明大几十倍。
  • 要在电路内部验证承诺（递归场景）→ IPA。配对在电路里太贵。

09小结与常见误区

你应该带走的

  • 多项式承诺 = 常数大小的「多项式指纹」+ 可验证的「某点取值」。
  • KZG 的承诺是 [p(τ)]₁，打开证明是 [(p(x)−v)/(x−z)]₁。
  • 验证等式 e(C−[v]₁,[1]₂)=e(π,[τ]₂−[z]₂) 在指数上等价于整除关系。
  • 隐藏性与绑定性不能同时统计安全，必须选一边。
  • FRI 用折叠降次，只要哈希；IPA 用内积递归，只要离散对数。
✕「承诺就是哈希，把多项式哈希一下就行。」
✓
普通哈希不能证明「某点取值」。你需要的是同态结构： [p(τ)] 必须能由系数线性组合出来。哈希是一团乱码，没有这种代数性质。
✕「KZG 只要把 τ 删了就没风险了。」
✓
删除的时机和方式才是风险所在。内存残留、swap、进程快照都可能泄露。 所以真实项目用 MPC 仪式，把单点故障变成「1-of-N 诚实即可」。
✕「FRI 证明大，所以它更差。」
✓
它换来了无信任设置 + 抗量子。在 L2 场景里，几十 KB 的证明分摊到几千笔交易上， 每笔只多几十字节 —— 代价可以忽略，收益却是结构性的。
✕「一个承诺只能打开一次。」
✓
KZG 可以对同一个承诺在任意多个点分别打开，每次产生一个独立的 π。但每次打开都会泄漏「该点的取值」，所以如果要证明多个点又不泄露多项式， 需要额外的盲化，或者用批量打开把多个点合并成一次。
