零知识变换：为什么加个随机数就够了

「零知识」不是「看起来没泄露」，而是一个严格的数学陈述： 存在一个不接触见证的模拟器，能造出与真实证明无法区分的假证明。 这一页讲这句话到底怎么证明，以及工程上靠什么实现它。

核心概念 ≈ 15 min 难度 3 / 5 前置：承诺 · 交互协议 后续：Groth16 / PLONK 的盲化

01这个模块要解决的问题

一个「可靠的」证明系统可能是完全泄露的。 比如：证明者直接把见证 w 发给验证者，验证者自己算一遍 R(x,w)=1。 这满足完备性和可靠性 —— 但它显然是「零知识」的反面。

所以「零知识」必须被单独定义、单独证明。而且它不能靠直觉： 「这个值看起来是随机的」不是数学。

问题在于：证明者发出去的东西，总得让验证者能检查。这些信息里必然包含了 某些关于见证的函数。零知识要求的是：这些函数值不提供任何超出「命题为真」的信息。

i
一句话判据

如果验证者能自己造出一份看起来一模一样的交互记录， 那他从真实交互里就什么也没学到 —— 因为「自己造」意味着不需要见证。 这就是模拟器思路的来源。

02直觉：把「证据」泡在噪声里

你要证明「我知道 x」，但又不能说出 x。直接说 x = 42 显然不行。 那说什么？

说一个被随机数掩盖过的 x。s = r + c·x： 如果 r 是均匀随机的，那么 s 在域上也是均匀随机的 —— 它和 x 的关系被完全打散了。

s = r + c·x   ⟹   s 的分布与 x 无关（当 r 均匀随机时） 给定 s，反推 x 需要知道 r；而 r 已经被丢弃了

但光有 s 还不够 —— 验证者要能确认 s 和 x 的关系。 所以还要给他一个「锚点」R = gr。有了 R、c、s， 他能验证 gs = R·Xc，但推不出 x。

✓
这就是「盲化」

用一个均匀随机量 r 把敏感值「平移」到一个随机位置。 因为平移量未知，观察者无法还原原始值。 所有零知识技术，本质上都是在找「合适的平移方式」。

03形式化定义：模拟器存在

零知识的严格定义不涉及「泄露多少比特」，而是关于分布不可区分。

定义（计算零知识）
存在一个多项式时间算法 S（模拟器），使得对任意验证者 V*、任意 (x, w) ∈ R，
都有   View⟨P(x,w), V*(x)⟩  ≈c  SV*(x) ≈c 表示「计算不可区分」：任何多项式时间区分器都分不出来
符号含义
View验证者在整个交互中看到的一切：所有消息、自己的随机数、时间顺序。
SV*(x)模拟器的输出。它只拿到公开输入 x，没有 w。
SV* 的上标模拟器可以「黑盒调用」验证者，看它会问什么 —— 这叫 rewinding（重放）。
≈c不存在多项式时间的算法能区分这两个分布，优势不可忽略。

注意定义的形状：「真实交互」和「模拟出的假交互」看起来一样。 既然模拟器没有 w 也能造出一样的记录，那真实交互里的 w 就没有产生任何「可观测的痕迹」。

!
为什么必须是「计算」不可区分

如果要求「统计不可区分」（连无穷算力也分不出），很多实用协议就不满足了。 Schnorr 的模拟器输出分布与真实分布完全相同，那是最强的一档； 但 Groth16 这类方案只能做到计算不可区分，依赖离散对数假设。

04Schnorr 的模拟器：先选答案，再倒推题目

这是理解零知识最好用的例子，因为它简单到可以完整写出来。 真实交互是「先承诺 R，再拿挑战 c，最后算 s」。模拟器把顺序反过来。

1

真实交互

证明者选 r → 发 R = gr → 收到 c → 算 s = r + c·x。

验证者看到的记录是 (R, c, s)，且满足 gs = R·Xc。

2

模拟器：先挑 c 和 s

随机取 c 和 s（都在 𝔽p 上均匀）， 然后反推 R：

R = gs · X−c 这样构造出来的 R 必然满足验证等式，因为它是被等式「解出来」的
3

输出 (R, c, s)

这份记录和真实交互分布完全相同。因为真实交互里 s = r + c·x， 当 r 均匀时 s 也均匀；而模拟器里 s 本来就是均匀选的。 两者都是「均匀随机的 s，配一个由等式决定的 R」。

✓
结论

模拟器没有用 x，却造出了完全一样的记录。 所以验证者从真实交互里能提取到的信息，他自己也能造出来 —— 也就是零。

05三种常用技术，以及它们分别防什么

技术做法防的是什么
随机化
randomization		 证明者每次用一个新随机数，重新「洗牌」 多次证明之间的关联分析（同一见证被反复证明）
盲化
blinding		 把敏感多项式加上随机倍数，例如 p(x) + r·Z(x) 承诺泄露系数信息
HVZK
honest-verifier ZK		 只对「诚实验证者」保证零知识，不防御恶意验证者 一个更弱但更容易证明的性质，通常配合 Fiat–Shamir 使用

盲化在 SNARK 里长什么样

证明者要承诺多项式 a(x)，但直接承诺会泄露系数。做法是加一个随机倍数：

a'(x) = a(x) + b1·Z(x) + b2·x·Z(x) b 是随机盲化因子；因为 Z(x) 在约束点上为零，加上它不改变任何约束的取值

这就是为什么 Z(x) = Π(x−ri) 这个「目标多项式」如此重要： 它在所有约束点上为零，所以加上它的倍数，等于「在合法解上什么也没改」， 但对外部观察者来说，承诺值彻底变了。

i
为什么至少要加两项

只加一项 b·Z(x) 时，盲化因子的自由度不足以掩盖所有系数信息 —— 攻击者可能通过多次打开反推出 a 的某些线性组合。 加上 x·Z(x) 这一项，才能保证在任意两个点上打开都安全。 Groth16 的证明里正好有 A、B、C 三个点，对应三组盲化因子。

06变成非交互之后，零知识会变弱吗

会。这是一个容易被忽略的细节。

交互式协议里，验证者每次给的挑战 c 都是新随机的，所以证明者可以放心地用一次性随机数。 但 Fiat–Shamir 之后，证明可以被无限次复制、转发 —— 如果同一份证明被用于多个场景，随机数的重用就可能导致泄露。

两个实际约束

  • 随机数必须真随机：用时间戳、计数器当 r，会让不同证明之间产生可预测的关系。
  • 盲化因子必须每次新生成：重用一个 b 去证明不同的命题，等价于泄露了两者的差。
!
这类错误的后果是静默的

证明依然能通过验证，可靠性没有任何问题。泄露只发生在「多次证明的联合分布」上 —— 单看一份证明完全正常。所以它极难通过功能测试发现，必须靠代码审计或形式化分析。

07小结与常见误区

你应该带走的

  • 零知识的定义是「存在模拟器」，不是「看起来随机」。
  • 模拟器没有见证，却能造出同分布的记录 —— 这才是「什么也没泄露」的证明。
  • Schnorr 的模拟器把顺序反过来：先选 c, s，再倒推 R = gsX−c。
  • 盲化的标准手法是加上 Z(x) 的随机倍数 —— 它在约束点上为零，不改变语义。
  • 非交互化之后，随机数复用会成为新的泄露面。
✕「证明里没有明文，所以就是零知识。」
✓
没有明文不等于零知识。承诺、群元素、多项式取值都可能携带关于见证的信息。 唯一的判据是能不能构造出模拟器。
✕「模拟器能造出证明，说明证明是假的。」
✓
模拟器是证明工具，不是攻击手段。它说明了「验证者看到的东西不含信息」， 而不是「证明本身无效」。真实的证明依然由真实的见证生成。
✕「加了随机数就一定零知识。」
✓
随机数加错位置会破坏完备性（验证不通过），加得太少会泄露，加得不可重复会引入新问题。 「加在哪、加几项、什么时候重新生成」都有严格约束。
✕「HVZK 就等于零知识。」
✓
HVZK 只对诚实验证者成立。恶意验证者可能偏离协议（比如选一个特殊的挑战）， 从而提取额外信息。要防住这种情况，需要更强的性质或额外的技术（如 Fiat–Shamir 后的模拟）。
