Sumcheck：一次消掉一个变量

前面所有方案都靠「把约束打包成多项式」。Sumcheck 换了个方向： 把「求和」这件事本身变成可验证的。 Spartan、Lasso、Binius、Jolt，以及几乎所有 zkVM，都建立在它之上。

现代主流路线 ≈ 16 min 难度 4 / 5 前置：多项式 · 概率抽样 被用于：Spartan · Lasso · zkVM

01这个模块要解决什么问题

很多计算最后都归结成一个求和：一个多元多项式在超立方体上所有取值的和，等于某个公开值。

H = Σx1,…,xn ∈ {0,1} g( x1, …, xn ) 一共有 2ⁿ 项。直接算要 2ⁿ 次求值 —— 对 n=30 就是十亿次

验证者当然不可能自己算这 2ⁿ 项。但如果证明者声称 H 是这个值， 验证者怎么用远少于 2ⁿ 的工作量确认？

Sumcheck 给出的答案是：按变量逐个验证，每轮只做常数次求值。 总共 n 轮，每轮把变量个数减一。

i
和 QAP 路线的根本区别

QAP 是「把约束编译成多项式，然后用承诺锁住」。Sumcheck 是 「让验证者跟着证明者逐层剥洋葱」，每一层都用一个随机点来检验上一层。 前者需要承诺整个多项式，后者只需要承诺少量求值。

02直觉：把 n 维立方体压成一维

想象一个 n 维的超立方体，每个顶点上有一个值。H 是所有顶点值之和。

第一轮：把「除第一个变量外」的所有变量都求和掉，得到一个只关于 x₁ 的一元多项式 g₁(x₁)。它只有两个点有意义：g₁(0) 和 g₁(1)。 如果证明者没说谎，g₁(0) + g₁(1) = H。

验证者检查这个等式，然后随机取一个点 r₁，要求证明者继续 「在 x₁ = r₁ 这个切片上」做同样的事。

Σx1 g1(x1) = H   ⟶   g1(r1) = Σx2… g(r1, x2, …) 第一轮的结论，变成第二轮的输入

重复 n 次，最后验证者手上只剩一个具体的点 (r₁,…,rₙ)， 直接求值 g(r₁,…,rₙ) 看是否等于证明者最后的声称值。

03协议的完整流程

把上面的直觉写成协议。证明者每轮发一个一元多项式，验证者每轮回一个随机点。

1

第 1 轮

证明者发 g₁(X₁) = Σx₂…xₙ g(X₁, x₂, …, xₙ)， 声称 g₁(0) + g₁(1) = H。

验证者检查这个等式，若通过，随机取 r₁。

2

第 i 轮

证明者发 gi(Xi) = Σxi+1… g(r₁,…,ri−1, Xi, …)， 声称 gi(0) + gi(1) = gi−1(ri−1)。

验证者检查，随机取 ri。

3

最后一轮

验证者拿到 r₁…rₙ，直接计算 g(r₁,…,rₙ)（这是一次求值）， 检查它是否等于证明者最后声称的值。

角色每轮做什么总工作量
证明者算出一个一元多项式（次数有界）O(2ⁿ) 一次，之后 O(2ⁿ)
验证者检查两个求值 + 取随机数O(n) 次域运算 + 1 次 g 求值
✓
关键的不对称

证明者仍然要做 O(2ⁿ) 的工作（他得真的把和算出来）， 但验证者只要 O(n)。这正好符合 SNARK 的目标： 把成本压在证明者身上。

04为什么是 O(log n)：次数界的作用

n 轮之后，验证者只做了 n 次检查。但总共 2ⁿ 项， 怎么可能只查 n 次就够？

答案在次数界上。如果 g 对每个变量的次数都不超过 d， 那么每轮的 gi 次数也不超过 d。

degXi g ≤ d   ⟹   每轮的 gi 只有 d+1 个系数要发 d 通常是 2 或 3，所以每轮通信量是常数

而两个不同的 d 次多项式，最多在 d 个点上相等。 所以证明者想在某一轮撒谎而不被发现，概率不超过 d/|𝔽|。

Pr[ 作弊成功 ] ≤ n · d / |𝔽| n 轮，每轮最多 d/|F| 的失败概率，用并集界累加

代入 n = 30、d = 2、|𝔽| = 2²⁵⁴： 失败概率约 2⁻²⁴⁴，可以忽略。

!
这就是为什么「次数界」是前提

如果 g 的次数没有上界（比如它是个任意函数），证明者可以发一个 「在随机点上恰好正确、但整体不对」的多项式，验证者无法区分。 Sumcheck 只对低次多项式有效，这不是可选的假设。

05Spartan：用 Sumcheck 重做 R1CS

Spartan（2020）的思路：R1CS 的约束 (Az)∘(Bz) = Cz 可以写成一个求和断言， 然后用 Sumcheck 验证，不需要 QAP、不需要 FFT。

Σi=1m eq(i, r) · [ ( Az )i ( Bz )i − ( Cz )i ] = 0 eq(i,r) 是「选择器」：随机点 r 让这个加权和在「所有约束都成立」时才为零

这个式子的好处：

  • 不用 FFT：省掉了 O(n log n) 的插值，证明者更快。
  • 不用可信设置：配合 FRI 或 IPA 就能做透明方案。
  • 证明更小：Spartan 的证明比 Aurora 小一个数量级。

省掉 FFT 到底省了多少

QAP 路线里，证明者必须做两次 NTT（一次正向、一次逆向），复杂度 O(n log n)。 对 n = 2²⁰ 的电路，这是几千万次域运算，占总时间的 20–40%。

环节QAP 路线Spartan 路线
多项式插值2 次 NTT不需要
约束检查多项式恒等式 + 承诺打开Sumcheck 的 n 轮
证明者内存要存整张系数表只需流式读取

但要注意：Sumcheck 换来了 n 轮交互（Fiat–Shamir 后是 n 次哈希）。 当 n 很小时，这个开销反而超过 NTT。交叉点大约在 n = 2¹⁶ 附近。

方案算术化核心技术可信设置

06GKR：给分层电路做 Sumcheck

GKR（Goldwasser–Kalai–Rothblum）针对的是分层电路： 每一层的每个门只连接上一层的两个门。大量 zkVM 的电路都是这个形状。

核心观察：每一层的输出，都可以写成「上一层取值的加权和」。 于是「这一层的某个门算对了」等价于「一个求和等式成立」—— 正好可以用 Sumcheck 逐层验证。

第 i 层：Vi(z) = Σx,y addi(z,x,y)·(Vi+1(x)+Vi+1(y)) + muli(z,x,y)·Vi+1(x)·Vi+1(y) add/mul 是布线选择子，决定第 z 个门是加法还是乘法

逐层往下推，最后落到输入层，验证者直接检查输入即可。 总验证成本与电路深度成正比，与宽度几乎无关。

i
GKR 的优势与局限

优势：证明者不需要承诺整张表，只需要承诺每一层的少量值。 对「深而窄」的电路特别友好。
局限：只适合分层结构。如果电路有大量跨层连接（比如稠密矩阵乘）， 层数会爆炸，反而不如 R1CS。

07MPC-in-the-head：另一条完全不同的路

前面所有方案都依赖「多项式 + 承诺」。这一支不用 —— 它把多方安全计算（MPC）协议搬到证明者脑子里演一遍。

思路分三步：

1

把见证切成 N 份

用秘密分享把 w 拆成 w₁…wN，单独任何一份都不泄露信息。

2

在「脑子里」跑一遍 MPC

模拟 N 个参与方，各自持有 wi，共同计算 R(x,w)。 每个人只看到自己的份额和广播值。

3

承诺所有视图，随机打开一部分

把 N 个参与方的完整视图都哈希承诺。验证者随机挑 t 个打开， 检查它们之间的一致性。

如果计算错误，至少有一个参与方的视图会暴露矛盾。 打开 t 个而没抓到的概率是 (1−1/N)t，重复几轮就能压到可忽略。

方案底层假设特点
Picnic对称密码（AES / SHA）抗量子、证明大（几十 KB）、签名场景
Ligero哈希 + 编码透明、证明中等、验证较快
!
为什么它重要，但用得少

它是少数不依赖任何数论假设的方案，抗量子。但证明体积大、 验证开销高，而且「把 MPC 协议写成电路」本身很麻烦。 目前主要用于数字签名（Picnic 是 NIST 后量子签名候选），而不是通用 ZKP。

08小结与常见误区

你应该带走的

  • Sumcheck 把「2ⁿ 项求和」压成「n 轮、每轮常数次检查」。
  • 每轮证明者发一个一元多项式，验证者回一个随机点，变量数减一。
  • 安全性依赖次数界：低次多项式在随机点上无法伪装。
  • Spartan 用 Sumcheck 重做 R1CS，省掉 FFT 和可信设置。
  • GKR 是「分层电路版」的 Sumcheck；MPC-in-the-head 是完全不同的抗量子路线。
✕「Sumcheck 是一种 SNARK。」
✓
它只是一个交互式协议，本身不提供零知识和简洁性。 要变成 SNARK，必须再加承诺（把每轮的多项式锁住）和 Fiat–Shamir（去交互）。
✕「Sumcheck 比 QAP 更快，所以应该全面替代。」
✓
它省掉 FFT，但引入了 n 轮交互（Fiat–Shamir 后是 n 次哈希）。 对小电路，QAP 的常数更优；对大电路，Sumcheck 的优势才显现。
✕「GKR 能证明任意电路。」
✓
只适合分层、低扇入的电路。稠密连接会让层数和每层的求和规模爆炸， 这时不如老老实实用 R1CS。
✕「MPC-in-the-head 是理论玩具。」
✓
Picnic 已经进入 NIST 后量子签名候选名单。它的价值在于 只依赖对称密码，这在后量子时代是稀缺属性。
