硬件加速：八成的算力花在两个操作上

不管你用 Groth16 还是 PLONK，证明生成的时间分布都惊人的一致： MSM 占 50–70%，NTT 占 20–40%。 优化这两件事，等于优化整个证明器；优化别的地方，基本是白费。

≈ 14 min 难度 3 / 5 前置：椭圆曲线 · FFT 产出：更快的证明服务

01先测量，再优化

「证明太慢」是症状，不是诊断。得先知道时间花在哪。

阶段占比能否并行
见证生成（填值）5–15%部分
MSM50–70%高度可并行
NTT20–40%高度可并行
域运算 / 哈希5–10%部分
序列化< 2%否

注意 MSM 和 NTT 都是数据并行的：每个点、每个蝶形互不依赖。 这决定了它们适合 GPU 和 FPGA，而不适合单核优化。

i
一个反直觉的事实

很多人第一反应是「优化域乘法」。但域乘法已经是纳秒级， 再怎么优化也只有 2–3 倍空间。而 MSM 的算法优化能带来 10–20 倍。 选对算法比选对指令集重要得多。

02MSM 为什么这么贵

MSM：C = Σi=1n ai · Pi n 个标量 × n 个椭圆曲线点，求和

朴素做法：每个 aiPi 用倍加算法算，需要 ~256 次点加。 总共 256n 次点加。n = 100 万时，就是 2.56 亿次点加。

每次点加要做一次域求逆（或至少一次乘法），在 254 位域上约 100 纳秒。 算下来 25 秒 —— 这只是 MSM，还没算 NTT。

为什么不能「预先算好」

因为 Pi 是承诺点，依赖电路和设置，每次证明都不同； ai 是见证，每次交易都变。 两边都在变，没有可复用的中间结果。

03Pippenger：把「逐个算」变成「分批算」

核心思想：不要分别算每个标量乘，而是把标量按二进制位「分桶」。

1

把标量切成窗口

每个 ai 按 c 位一组切开（比如 c = 16）。

2

同窗口值的点加到一起

对每一组，把「窗口值相同」的 Pi 累加到一个桶里。 桶的数量是 2c。

3

跨桶累加

从高位桶开始，做「累加器 = 累加器 + 桶」并倍点，逐位推进。 这一步把 2c 个桶压缩成一个结果。

复杂度：O( n · λ / log n )   而非   O( n · λ ) λ 是标量位宽（254）。n 越大，节省越明显
n朴素Pippenger加速
210~ 26 万次点加~ 2 万次13×
216~ 1600 万次~ 30 万次50×
220~ 2.7 亿次~ 2000 万次130×

04GPU：目前性价比最高的选择

显卡有几千个核心，正好适合 MSM 和 NTT 这种「同一操作重复几百万次」的负载。

方案特点典型加速
ICICLEIngonyama 开源，支持 CUDA，集成到多个框架10–30×
cuZK学术方案，针对 Groth16 优化10–20×
自研 CUDA深度定制，能榨干硬件20–50×

GPU 的真实瓶颈：显存带宽

MSM 是「读大量点、做少量运算」的负载，瓶颈在显存带宽而不是算力。 一个 100 万点的 MSM 需要读 32 MB 的点数据，来回几次就吃掉大部分时间。

所以优化重点往往不是「算得更快」，而是「减少数据传输」：把点压缩存储、 把桶放在片上内存、把结果批量回传。

!
别忽略 PCIe 传输

把数据从 CPU 内存拷到显存要时间。如果每次证明都重新传一遍，可能抵消掉 GPU 的加速。 生产系统会在显存里常驻设置参数（proving key），只传见证。

05FPGA 与 ASIC：快，但不灵活

硬件优势劣势适合谁
CPU灵活、便宜、好部署核数少所有人（起步）
GPU性价比高、生态成熟显存限制、功耗中型证明服务
FPGA功耗低、可重配置开发周期长、需要硬件工程师大型矿场式部署
ASIC极致能效流片成本极高、算法一变就废几乎没人做（ZKP 算法还在演进）

ASIC 在 ZKP 领域几乎没有实际部署，原因很现实：算法变化太快。 一颗芯片流片要两年，两年后可能整个证明系统都换了。风险收益比不划算。

i
一个例外：Filecoin 的矿机

Filecoin 的 PoRep 用固定的 Groth16 电路，算法稳定，所以出现了专用硬件。 这说明只有算法冻结的场景才值得做 ASIC。

06分布式证明：一台机器不够怎么办

当电路大到单机内存放不下（比如 2²⁸ 约束，需要上百 GB）， 就必须把证明拆分到多台机器。

拆分的两种粒度

粒度怎么拆通信开销
按操作拆MSM 分片到多台机器，各自算一部分再汇总低（只汇总最终点）
按电路拆把电路切成子电路，各自生成证明再聚合高（要处理跨片连线）

第一种简单，但受限于「单次 MSM 的规模」；第二种能处理任意大的电路， 但切分本身会引入额外的约束（用于连接子电路）。

代表方案

  • Snarkify：把证明流程容器化，按阶段分布式调度。
  • =nil; Foundation：把电路编译成「证明市场」可执行的任务。
  • Gensyn：把训练验证拆成可并行的子任务。

共同思路：把「证明生成」变成一个可水平扩展的服务， 而不是一个单机程序。

07小结与常见误区

你应该带走的

  • MSM 占 50–70%，NTT 占 20–40%，其他都是零头。
  • Pippenger 把 MSM 从 O(nλ) 降到 O(nλ/log n)，n 大时加速上百倍。
  • GPU 的瓶颈是显存带宽，不是算力。
  • FPGA 适合稳定负载，ASIC 在 ZKP 里基本不可行（算法变太快）。
  • 超大电路靠分布式拆分，按操作拆比按电路拆简单。
✕「上 GPU 就能快十倍。」
✓
要看你有没有把数据放在显存里、有没有用对算法。 一个没优化的 CUDA 实现，可能比优化过的 CPU 还慢（因为传输开销）。
✕「优化编译器比优化运行时更有效。」
✓
编译器能减少 20–30% 的约束，但 MSM 的算法优化能带来 10–20 倍。 先看瓶颈在哪，再决定优化哪一层。
✕「多卡并行就是线性加速。」
✓
受限于通信和同步。MSM 分片的扩展性较好（接近线性）， 但 NTT 的分片需要频繁交换数据，通常只能做到 60–80% 效率。
✕「硬件加速能解决所有性能问题。」
✓
如果电路本身有十倍冗余（比如该用查表的地方用了逐位分解）， 加速硬件只是把浪费算得更快。先优化约束，再优化硬件。
