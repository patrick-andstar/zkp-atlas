编码理论：FRI 靠「离码字多远」判断次数

FRI 要在不看全部系数的情况下，确认「这个多项式次数不超过 d」。 它用的不是代数，是距离：把多项式在更多点上求值，变成一串码字； 次数超了，这串值就会离所有合法码字很远。

≈ 13 min 难度 3 / 5 前置：多项式与 FFT 被用于：FRI · STARK · 数据可用性

01这个模块要解决什么问题

KZG 证明「多项式在某点的取值」很容易：配对一下就完了。 但 FRI 要证明的是另一件事：「这个多项式的次数不超过 d」。

为什么这件事重要？因为在 STARK 里，如果证明者能用高次多项式冒充低次， 他就可以在「不该有自由度的地方」塞入额外的值，从而伪造证明。

麻烦在于：验证者不能读全部系数（那样证明就 O(n) 了）。 他只能抽查若干个点的取值。那么，抽查能判断次数吗？

i
答案是「能，但需要一个前提」

单看几个点当然判断不了。但如果把多项式在远多于其次数的点上求值， 得到的这串值就有了「冗余」—— 冗余让高次多项式无处躲藏。 这就是编码理论登场的地方。

02直觉：为什么「多写几遍」能发现造假

你要确认一个人报的数「不超过 10」。他只报了 3 个数：2、5、7。你能判断吗？不能。

但如果要求他在 100 个位置都报数，而且这些数必须落在一条「次数 ≤ 10 的曲线」上 —— 那么他只要有一个位置乱报，整条曲线就对不上了。

9 个系数  ⟶  在 100 个点上求值  ⟶  100 个数 信息被「拉长」了 11 倍。这 11 倍冗余就是检查的抓手

编码理论把这个直觉形式化：合法的低次多项式，其求值向量构成一个「码」； 任何不在码里的向量，离码里所有元素都有一定距离。

03Reed–Solomon 码：把多项式变成码字

消息：  m = ( m0, m1, …, mk−1 )  ⟶  多项式 p(x) = Σ mixi
码字：  ( p(α0), p(α1), …, p(αn−1) )  ∈  𝔽n α 是 n 个互不相同的点；n > k 时就有冗余
参数含义典型取值
k消息长度 = 多项式次数 + 1电路规模的函数
n码字长度 = 求值点数通常取 4k 或 8k
ρ = k/n码率（rate）。越低冗余越大，检查越容易1/4 或 1/8
d最小距离，见下一节n − k + 1

码率是理解 FRI 成本的关键：ρ = 1/4 意味着证明者要把数据「写 4 遍」。 写得多，检查就容易（抽几个点就能发现问题）；但证明也变大。

04距离：RS 码为什么是最优的

「距离」指两个码字在多少个位置不同。RS 码有一个极强的性质：

dmin = n − k + 1 这叫 MDS（最大距离可分）性质，是码理论里的最优界

为什么？因为两个不同的、次数都小于 k 的多项式，最多在 k−1 个点相等 （相减后是次数 ≤ k−1 的多项式，最多 k−1 个根）。 所以它们在 n 个点上至少 n−(k−1) 个位置不同。

p ≠ q,   deg p, deg q < k  ⟹  |{ i : p(αi) ≠ q(αi) }| ≥ n − k + 1

这个下界是「免费」的：不需要任何额外结构，只靠多项式的根的个数定理。 这就是 RS 码在 ZKP 里如此受欢迎的原因。

!
注意「距离」是对码字说的，不是对值说的

一个随便乱写的向量，与最近的合法码字的距离可能很小（如果它只错了一两个位置）。 FRI 要保证的是：如果证明者在某处作弊，他必须改掉很多位置才能回到码里 —— 而那些位置会被随机抽查抓到。

05低度测试：从「距离」到「次数」

这是 FRI 的核心命题，也是编码理论在 ZKP 里最重要的一次应用。

命题：设 f 在 n 个点上取值，码率 ρ = k/n。
若 f 与所有次数 < k 的多项式的距离都 > δ，则称 f 是 δ-远离的。
低度测试要区分：f 在码里  vs  f 远离码。

朴素做法是查全部 n 个点，O(n)。FRI 把它降到了 O(log² n)，靠的是折叠：

1

把 f 拆成偶数项和奇数项

f(x) = feven(x²) + x·fodd(x²)

2

用随机 α 组合成新多项式

f'(x) = feven(x) + α·fodd(x)，次数减半。

3

递归，直到次数变成常数

每轮规模减半，共 log k 轮。每轮只需检查一个随机点的一致性。

为什么折叠能保持「低度性」？因为如果 f 是低次的，f' 必然也是低次的（次数减半）。 反过来，如果 f 是远离的，折叠后大概率仍然远离 —— 这一步的严格证明依赖编码理论的 「距离保持」性质，是 FRI 论文的技术核心。

i
为什么码率要取 1/4 而不是 1/2

码率越低，距离越大，折叠后「远离性」保持得越好，需要的查询次数越少。 但码率低意味着求值点更多、证明更大。1/4 是安全性与体积的常用折中； 有些实现用 1/8 换取更少的查询轮次。

06FRI 的完整验证流程

步骤证明者验证者
1承诺 f 在 n 个点的求值（Merkle 树）—
2—发随机挑战 α₀
3折叠得到 f₁，承诺它—
4…… 重复 log k 轮 ……每轮发新的 α
5发送最后那个常数多项式直接检查次数
6—回查：对每轮随机选若干位置，要求打开对应的 Merkle 路径，验证折叠关系成立

最后一步是关键：验证者不是「相信」每轮都对，而是抽查。 每一轮抽 q 个位置，作弊被发现的概率是 1 − (1−δ)q。 取 q ≈ 30、δ ≈ 1/4，漏检概率就降到可忽略。

Pr[ 作弊未被发现 ] ≤ ( 1 − δ )q δ 是「远离度」，q 是每轮查询次数；这是 FRI 可靠性的来源

07一个能手算的小例子

取 k = 3（次数 < 3），求值点 n = 6，码率 ρ = 1/2。

消息 (1, 2, 3) 对应 p(x) = 1 + 2x + 3x²，在 x = 0,1,2,3,4,5 上求值：

x012345
p(x)1617345786

如果证明者偷偷加一个高次项

把 p 改成 p*(x) = p(x) + x⁵（次数变成 5，已经超出 k=3）：

x012345
p*(x)174927710813211

在 6 个点里有 5 个和原来不同（只有 x=0 相同）。 也就是说，它离任何低次码字都很远，随机抽一个点就有 5/6 的概率发现问题。

✓
这就是冗余的作用

如果只存 3 个系数，证明者加一项你根本看不出来。 存了 6 个求值点，多出来的 3 个就是「检查余量」。 FRI 把这件事做到 log n 层，每层都留余量，最终用极少的抽查覆盖全部。

08小结与常见误区

你应该带走的

  • RS 码 = 把多项式在 n 个点上求值，n > k 产生冗余。
  • 最小距离 d = n − k + 1，来自「次数 < k 的多项式最多 k−1 个根」。
  • 低度测试：区分「在码里」和「远离码」，靠距离而非系数。
  • FRI 用折叠把规模减半 log k 次，每轮抽查若干个点。
  • 可靠性 ≤ (1−δ)q，δ 是远离度，q 是查询次数。
✕「编码理论就是纠错码，和 ZKP 没关系。」
✓
FRI、STARK、以及所有基于哈希的证明系统，核心都是低度测试， 而低度测试的理论基础就是编码理论的距离性质。没有它，就没有「不用配对也能验证」这条路。
✕「码率越小越安全，所以取 1/100 最好。」
✓
码率小意味着求值点数量爆炸，证明体积和生成时间同步增长。 存在一个最优区间（通常 1/2 到 1/8），再低就是浪费。
✕「抽查 30 个点，作弊概率是 30/n。」
✓
不是线性关系。失败概率是 (1−δ)q，指数衰减。 这正是抽查有效的原因：30 次查询就能把漏检概率压到 10−4 以下。
✕「FRI 只证明次数，不证明内容。」
✓
对。次数只是「形状」。要证明「内容正确」，还需要约束多项式： 把「必须满足的规则」写成多项式，再验证它在码字上为零。两者结合才是完整的 STARK。
